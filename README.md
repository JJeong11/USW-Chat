# 👩‍👧‍👧💬 SuChat 

수원대학교 학생들이 학교 이메일 인증을 거쳐, 원하는 활동에 따라
새로운 학우와 실시간으로 대화할 수 있는 1:1 랜덤 채팅 앱입니다.

- 팀 구성 | 9명
- 담당 역할 | 백엔드 개발
- 원본 저장소 | [USW-Random-Chat/JavaSpring](https://github.com/USW-Random-Chat/JavaSpring)

## ⛏ 사용한 기술

Java 11 · Spring Boot · Spring Security · Spring Data JPA · Redis · WebSocket(STOMP)

## 배경과 목적

**즉시 교류의 어려움 및 교내 구성원 확인의 한계**

### 배경
- 기존 학교 커뮤니티에서는 함께할 학우를 찾으려면 게시글을 올리고 답변을 기다려야 합니다.
또한 일반 익명 채팅에서는 상대가 같은 학교 학생인지 확인하기 어렵습니다.
### 목적
- SuChat은 학교 이메일로 교내 구성원을 확인하고, 공강·식사·공부 등
같은 활동을 원하는 학우끼리 1:1로 연결해 교내 교류를 돕고자 기획했습니다.

## 주요 기능

- 학교 이메일 인증을 통한 회원가입
- 활동 카테고리별 1:1 랜덤 매칭
- 매칭된 학우와 실시간 채팅

## 📌 담당 역할

- **Redis 기반 1:1 랜덤 매칭 로직 설계 및 구현**  
  매칭 요청 접수부터 대기열 관리, 매칭 대상 선정, 참가자 정보 저장까지 전 과정을 담당했습니다.
  Redis Sorted Set에 사용자 ID와 요청 시각을 저장해 중복 대기를 방지하고,
  먼저 요청한 두 사용자를 매칭했습니다. 매칭이 완료되거나 요청이 취소되면
  해당 사용자를 대기열에서 제거하도록 구현했습니다.

- **학교 이메일 인증과 회원 기능 연동**  
  학교 이메일 인증 여부를 회원가입 흐름에 연결하고,
  인증된 사용자만 아이디 찾기 메일을 받을 수 있도록 구현했습니다.

  - **이메일 인증 기반 회원가입 흐름 설계**  
  이메일 인증 전에는 가입 정보를 임시로 보관하고, 인증을 완료한 뒤 정식 회원으로 등록하는 흐름을 설계했습니다.
  임시 회원 정보의 저장소로 Redis를 제안했습니다.

- **JWT 인증 오류 및 공통 응답 처리**  
  Access Token 만료, Refresh Token 만료·불일치 등 오류 상황을 구분하고,
  전역 예외 처리로 공통 오류 응답 형식을 적용했습니다.

- **Spring Boot 기반 데이터 접근 및 예외 처리**
  - **JPA 더티 체킹** — 학교 이메일 인증 완료 시 트랜잭션 내에서 회원의 인증 상태를 변경해,
    별도의 `save()` 호출 없이 DB에 반영했습니다.
  - **Spring AOP** — Repository 계층에서 발생하는 JPA 예외를 Spring의 `DataAccessException`으로 변환하고,
     전역 예외 처리에서 공통 오류 응답을 반환하도록 구현했습니다.

## 👍 INSIGHT 👍 
1. 실시간 기능은 성공 경로보다 상태 전이와 실패 조건을 먼저 설계해야 합니다.

2. JPA는 트랜잭션과 영속성 컨텍스트를 함께 이해해야 안정적으로 사용할 수 있다.
